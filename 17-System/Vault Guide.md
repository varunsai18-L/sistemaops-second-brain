# Vault Guide

## Overview
This document provides comprehensive guidance on using, navigating, and maintaining the Obsidian knowledge vault.

## Purpose
To ensure consistent usage, maintenance, and evolution of the knowledge vault across all team members and stakeholders.

## Getting Started

### Vault Structure Overview
See [[Folder Structure]] for detailed organization principles.

### Navigation Best Practices
- Use [[WikiLinks]] for internal linking
- Utilize [[tags]] for cross-referencing
- Leverage [[Graph View]] for visual connections
- Use [[Daily Notes]] for daily logging

## Core Features

### Templates
- Located in `Templates/` folder
- Use consistent templates for meeting notes, project plans, etc.
- Reference: [[Templates]]

### Tags and Taxonomy
- Follow [[Naming Conventions]] for tag creation
- Use hierarchical tags where appropriate (e.g., `#project/initiative-name`)
- Review tags quarterly via [[Maintenance Checklist]]

### Workflows
- Capture → Process → Organize → Review
- Weekly review process outlined in [[Maintenance Checklist]]
- Quarterly review and archiving procedures

## Best Practices

### Note Creation
- Use clear, descriptive titles following [[Naming Conventions]]
- Include creation date in YYYY-MM-DD format in frontmatter
- Tag appropriately for discoverability
- Link to related notes when creating

### Linking Strategy
- Use bidirectional links liberally
- Create MOCs (Maps of Content) for complex topics
- Regularly review orphaned notes via [[Maintenance Checklist]]

### Maintenance
- Follow the [[Maintenance Checklist]] schedule
- Archive completed projects quarterly
- Review and update links monthly
- Backup vault regularly (automated via sync)

## Troubleshooting

### Common Issues
- **Sync conflicts**: Resolve via Obsidian's conflict resolution interface
- **Broken links**: Use the "Broken links" feature in Settings
- **Performance issues**: Archive old notes, review plugins

### Getting Help
- Consult this guide first
- Refer to [[Folder Structure]] for location questions
- Check [[Naming Conventions]] for naming questions
- Escalate to knowledge management team for complex issues
